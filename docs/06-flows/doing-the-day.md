# Doing the Day

## Purpose

This flow defines what the app does while the user is working: the
now line, focus mode, contextual nudges, and the prep card. It
exists because the middle of the day is where the app must be
invisible until it is useful — and then useful immediately.

The theme is: **be quiet, then be exactly right.**

## Invariants

- The now line is always visible in the Calendar and in the header of
  every other mode (`02-architecture/projections.md`). Within the
  Calendar it lives in the mode's header, so it is present in the week,
  month and year views as well as the day view.
- Focus mode suppresses all nudges
  (`03-experience/attention-budget.md`).
- Contextual nudges fire at most once per hour and never during an
  event.
- The prep card fires before events, not during them.
- Nothing in this flow requires the user's input. Every surface is
  either informational or optional.

## Specification

### The now line

A single line, always present, in every mode's header:

    NOW: Design review in 18 min

or:

    NOW: Draft Q4 plan (in progress)

or:

    NOW: Nothing scheduled — [Capture]

Sources, in order:

1. An active focus session, if one is running.
2. The current event, if one is in progress.
3. The next event today, if one is within 2 hours.
4. The next scheduled task today.
5. The top-priority open task.
6. "Nothing scheduled — [Capture]."

**Why capture and not "pick a task" here.** This source fires only when
there are no events and no open tasks — if any open task existed, source
5 would have caught it. So an action that offers to pick a task has
nothing to pick. Capture is the only action that works in the state that
shows it, and capture is available from every mode.

Tapping the now line opens the relevant surface: focus session,
event detail, or task detail.

The now line is not a nudge. It does not consume attention budget.
It is a persistent instrument.

**It does not scroll.** The Day view scrolls under it
(`05-modules/calendar.md`, "The fold"), because an instrument that leaves the
screen when you read is not always present. In every other mode the now line is
in a header that does not scroll either.

**The week view draws it twice, on purpose.** Its grid carries a now *rule*
across all seven columns, because a continuous time axis with no "you are here"
on it is unreadable — and in a week, now is a line rather than a point. The
header keeps the textual line, and the rule is the same fact drawn for the axis.
This is the only place in the app where one fact is stated twice on one screen,
and it is allowed because the two statements answer different questions: what is
next, and where am I in the day.

### Focus mode

Started from a task detail ("Start focus") or from the now line.
Optionally with a duration (default 25 minutes, configurable).

While active:

- A small indicator appears in the now line: "Focus: Draft Q4
  plan (18:42 left)."
- The calendar day view dims everything except the current time
  block.
- All nudges are suppressed.
- The app does not pop, ring, or vibrate for anything except
  system-level alerts (calls, texts) that the OS handles.

Ending focus:

- Manual end (tap the indicator → "End focus").
- Timer end (a subtle chime, optional).
- Leaving the app for more than 10 minutes.

On end:

- No "you focused for X" popup.
- No summary. The session is logged as a task event (not a
  separate entity).
- The now line reverts to its next source.

### Contextual nudges

Fired by the attention queue
(`03-experience/attention-budget.md`). The queue decides; this flow
defines what a contextual nudge *is*:

- A quiet in-app banner (or a push notification if the app is
  closed), e.g.:
  - "20 min before your 3pm — enough for a quick task?"
  - "No events for the next 45 min. Start focus?"
  - "Your 11am was cancelled. Try 'Draft Q4 plan'?"

The nudge is actionable:
- Tap the action text → performs the action.
- Swipe left → dismiss.
- Tap elsewhere → dismisses, no action.

Contextual nudges:

- Fire at most once per hour.
- Never fire during focus or an event.
- Never fire during quiet hours.
- Score by urgency, relevance, novelty, and history
  (`03-experience/attention-budget.md`).
- Are one surface, however the trigger is shaped. The gap nudge,
  the cancelled-event nudge, and the quick-task nudge are
  `contextual` variants, not surfaces of their own. They have no
  `SurfaceId` and no separate toggle (ADR 0013).

### The prep card

Fires 10 minutes before an event that has linked People (or a
non-empty note attached to it).

Content:

- Title, time, location.
- Attendees (linked People).
- Last note about each attendee.
- Last completed task with each attendee.
- Open tasks linked to each attendee.
- A suggested focus, generated by Tier 2 "Prep me"
  (`04-ai/tier-2-contextual.md`).

The prep card:

- Fires once per event, subject to the hourly cap
  (`03-experience/attention-budget.md`).
- Does not fire for events without linked People or attached notes.
- Is dismissable with a swipe.
- Counts as a nudge against the hourly cap. A user with
  back-to-back meetings in the same hour will see the prep card for
  the first meeting; subsequent prep cards for meetings within the
  same hour are suppressed. This is intentional: a dense meeting day
  is exactly when the app should be quietest. The user can always
  tap an event to see its prep card manually.

### The gap nudge

When the calendar has a gap of ≥ 20 minutes and the user is not in
focus, the queue may fire a gap nudge:

    "40 min gap. Pick a task?"
    [Draft Q4 plan]  [Call contractor]  [Something else]

The suggestions are open tasks that fit the gap length based on
user-estimated duration (if available) or a heuristic. The user
taps one → starts focus on it.

**The nudge does not fire without a candidate.** If no open task fits the
gap, the suggestion row would be empty and the nudge would offer to pick a
task with nothing to pick — the same defect the now line's sixth source was
corrected for above. The queue skips it.

A gap nudge is a `contextual` variant, not a surface of its own: it
spends the `contextual` slot and shares its urgency band and TTL, has
no `SurfaceId`, and has no toggle of its own. It is subject to the
hourly cap and the general nudge rules
(`03-experience/attention-budget.md`, ADR 0013).

### Running in the background

If the app is not in the foreground:

- The now line does not update. It is a foreground element.
- Nudges may fire as push notifications (if enabled).
- Focus timers continue and end with a notification.
- The calendar and health sync continue (platform permitting).

On foreground, the now line updates immediately.

### Ending the day

The "doing the day" flow transitions to the "shutdown" flow
(`06-flows/shutdown.md`) when:

- The user taps "Close day" from the command palette.
- The user opens the app after the day boundary and the previous
  day was not closed.

In both cases, shutdown surfaces.

## Examples

**A typical afternoon.**

    NOW: Design review in 18 min

    User keeps working. At 10 minutes before the event, the prep
    card appears:
      "Design review with Sarah — 11:00"
      Last talked: 3 weeks ago.
      Last note: "She mentioned wanting to try pottery."
      Suggested focus: Follow up on the onboarding flow.
      [Dismiss]

    User reads it, dismisses it.
    At 11:00 the event starts.
    The now line updates: "NOW: Design review (ends in 42 min)."
    No nudges fire while the event is active.

    At 12:00 the event ends. The gap nudge may fire in the next
    hour if a gap exists.

**Focus mode.**

    User opens a task, taps "Start focus."
    Timer starts at 25:00.
    Now line: "Focus: Draft Q4 plan (24:59 left)."
    The user works.
    No nudges fire, even if the queue has candidates.
    Timer ends with a subtle chime.
    Now line reverts to "NOW: 1:1 with Mark in 45 min."

**A cancelled event.**

    User's 11:00 event is cancelled in Google Calendar.
    Sync pulls the cancellation.
    The attention queue has a contextual nudge:
      "Your 11am was cancelled. Try 'Draft Q4 plan'?"
    Fires (if no nudge has fired in the last hour).
    User taps the suggestion → focus starts.

**A long gap.**

    The user's day has a 90-minute gap between 13:00 and 14:30.
    Queue fires:
      "90 min gap. Long enough for deep work?"
      [Draft Q4 plan]  [Something else]
    User taps "Draft Q4 plan."
    Focus starts with a 90-minute timer (adjusted to the gap).
