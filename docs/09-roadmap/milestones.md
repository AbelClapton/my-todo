# Milestones

## Purpose

This doc defines the checkpoints between phases in the build order.
Each milestone is a testable claim about the app's state. It exists
so progress can be assessed objectively, not by feel.

## Invariants

- Every milestone is testable. It is either true or false.
- A milestone is not a release. It is a checkpoint.
- Milestones are cumulative. Later ones assume earlier ones.
- A milestone is met when every criterion passes.

## Specification

### M0 — Local task tracker

**Claim:** The app can create, list, complete, and defer tasks
locally, with a real event log underneath.

Criteria:

- [ ] Event log schema exists in SQLite.
- [ ] All `task.*` event types are defined.
- [ ] All `day.*` event types are defined (`day.opened` at minimum).
- [ ] `append(entry)` writes to the log.
- [ ] `task_list` projection computes from the log.
- [ ] Tasks mode renders, with `row-default` and `row-rich` rows.
- [ ] Swipe right completes; swipe left defers.
- [ ] Completion is undoable within 5 seconds.
- [ ] Onboarding flow runs seven screens.
- [ ] No arbitrary Tailwind values pass the linter.

### M1 — The Day

**Claim:** The app has a calendar as the hub, with the day as the
atomic unit.

Criteria:

- [ ] Day projection computes from the log.
- [ ] Calendar day, week, month, and year views render.
- [ ] Daily Note is auto-created.
- [ ] In-app events can be created and edited.
- [ ] Attention budget queues and caps nudges.
- [ ] Shutdown flow runs three prompts and commits.
- [ ] Morning plan runs and commits three tasks.
- [ ] Now line updates from the day projection.
- [ ] Onboarding skip lands on the Calendar day view with default
      Areas seeded.

### M2 — Four modes

**Claim:** The app has all four modes with consistent gestures,
motion, and haptics.

Criteria:

- [ ] Habits mode renders; habit compliance computes.
- [ ] Notes mode renders; notes attach to edge 11's target set
      (Task, Event, Habit, Protocol, Day, Person).
- [ ] Capture flow works (pull-down, sort ritual).
- [ ] Daily obligations card surfaces once per day.
- [ ] Gesture vocabulary is identical across all modes.
- [ ] Motion vocabulary is identical across all transitions.

### M3 — On-device AI

**Claim:** The app feels smart without a network.

Criteria:

- [ ] Tier 1 parses typed input in < 200ms.
- [ ] Semantic search returns results in < 300ms.
- [ ] Command palette runs commands and direct matches.
- [ ] Tier 2 "Break this down" and "Find related" propose.
- [ ] AI constitution (all eight rules) is present in every prompt.

### M4 — Protocols and People

**Claim:** The app supports self-experimentation.

Criteria:

- [ ] Protocol entity exists; proposal, adoption, baseline,
      active, review.
- [ ] Protocol immutability is enforced by both the UI and the
      projection layer (forbidden entries are ignored; see
      `05-modules/protocols.md` and `02-architecture/projections.md`).
- [ ] People module renders; tasks and events link.
- [ ] Areas and Goals exist as filters and parents.
- [ ] Review module renders; weekly, monthly, and annual reviews
      are composed. The Tier 3 narrative arrives in M5.
- [ ] Resurfacing fires on schedule, subject to the attention
      budget.
- [ ] Streak milestones fire at 30 days.
- [ ] Lapsed-recovery flow runs with two equal doors.

### M5 — Cloud AI

**Claim:** The full AI surface is available.

Criteria:

- [ ] Tier 3 assistant runs simple queries locally and complex
      queries in the cloud.
- [ ] Research pipeline runs and returns cited results.
- [ ] Protocol reports generate with baseline vs. active.
- [ ] Weekly review narrative is generated by Tier 3.
- [ ] AI audit mode lists every `ai.proposed`, `ai.applied`, and
      `ai.rejected` entry.
- [ ] Cost tracking matches the provider's usage reports within 5%.
- [ ] Research quota is enforced.

### M6 — Sync and Auth

**Claim:** Multi-device with account.

Criteria:

- [ ] Auth flow completes with magic-link.
- [ ] Sync engine pushes, pulls, merges.
- [ ] Two devices converge on the same state.
- [ ] Initial sync streams the full log.
- [ ] Sensitive data defaults to local-only.
- [ ] Account deletion tombstones the server log.

### M7 — Integrations

**Claim:** The app is fed by the user's real life.

Criteria:

- [ ] Calendar sync works with Google, Apple, and Outlook.
- [ ] Contacts import works.
- [ ] Health auto-fills at least one habit type.
- [ ] Email forwarding creates captures.
- [ ] Weather renders in the day view.

### M8 — Shell apps

**Claim:** iOS and Android apps ship.

Criteria:

- [ ] Capacitor wraps the web app.
- [ ] Native STT, haptics, secure storage, share sheet work.
- [ ] Safe areas and keyboard are handled.
- [ ] App Store and Play Store submissions accepted.

### M9 — Polish

**Claim:** The app feels high-grade in the small details.

Criteria:

- [ ] Every transition uses the motion vocabulary.
- [ ] Every haptic uses the haptic vocabulary.
- [ ] Every screen passes the visual regression suite.
- [ ] Every screen passes axe accessibility.
- [ ] Cold start is < 3s on a mid-range phone.
- [ ] No arbitrary Tailwind values anywhere in the codebase.
- [ ] Semantic search works offline (keyword fallback).

## Examples

**Assessing M0.**

    Run the test suite. Check each criterion.
    M0 is met when all 10 are true.
    Do not move to M1 until M0 is met.

**A partially met milestone.**

    M3 criterion "Tier 1 parses in < 200ms" fails on an older
    phone (takes 350ms).
    M3 is not met.
    Optimize the parser, or accept the miss and document it.

**A milestone met but not shipped.**

    M5 (Cloud AI) is met in development. It is not shipped until
    M6 (auth) is met, because cloud AI requires auth.
    Milestones are cumulative and shipping requires them all.

## What this doc must NOT do

- This doc does not estimate time. It defines criteria.
- This doc does not define what each feature does. It references
  the module and flow docs.
- This doc does not lock in a release schedule. Milestones are
  checkpoints, not dates.
- This doc does not enumerate every test. It enumerates the
  criteria. Tests are implementation.
