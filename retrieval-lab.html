Lab 12 · the surfaces that route through one layer

Retrieval

retrieval.md is the flow with the widest licence in the set: "Retrieval is not one feature. It is a set of surfaces that all route through the same underlying tools." Four surfaces, one layer, and the layer is specified as tightly as anything else in the app.

So this lab looks for the seams. Every disagreement here is between a doc and the doc it cites — the surface table against the flow, the flow against its own examples, the layer against the invariant that quotes it. Three of them are counting errors: a list that is one short, an owner that names the consumer, and a chord with three claimants.

The four surfaces

surfaces.md is the inventory: every surface in the app, with its Kind — Mode, Screen, Overlay, Card, Control, Ambient — and the doc that defines it. Its retrieval table has four rows, and all four surfaces are specified somewhere. Nothing is missing.

The owners are the problem. Three of the four rows name a document that describes the surface from the outside, and one names a container that the doc specifying it does not give. A consumer is not a definer, and a table whose whole purpose is to say who owns what is the one place that cannot be sloppy about it.

Why this matched

The invariant is the feature: "Every result includes a 'why this matched' line (04-ai/retrieval-layer.md)." The parenthetical makes it a citation, so the line's existence should be checkable in the layer. The layer has twelve tools and exactly one of them returns a reason string.

Then check the flow against its own examples, which is where this pattern always breaks. A command row has no match to explain, a keyword row explains itself by the words it highlights, and the one row class that genuinely needs the line is also the one whose shape three docs draw three different ways.

The invariant's real scope

It is a rule about semantic results that is written as a rule about all results. Narrowed to its producer it becomes checkable, and the three classes it sheds each already have an explanation of their own.

Changed
The invariant reads: "Every semantic result includes a 'why this matched' line." The other three classes are named, with their own explanation, so the rule is total by exclusion rather than by overreach.
Cost
The invariant gets longer and weaker-sounding. It is the same invariant the layer implements, so the doc and the code agree for the first time.
Against rules
An invariant in this set is supposed to be verifiable. "Every result" is not, because a result is four different things. Naming the class makes the same sentence testable, which is what the other invariants in this doc already are.

What degrades

Two sentences count the same thing. The invariant: "Search works offline. Only semantic search may degrade to keyword-only when offline." The section that implements it lists five features and closes: "Only 'Ask: …' is unavailable, with a note."
