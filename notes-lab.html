Lab 06 · the connective tissue

Notes

Notes are the only module that is two things at once — a home (a list and an editor) and an attachment every other module can have. Its spec is the shortest in the doc set and it contains the app's longest list of separate surfaces.

The one component is a row specified at row-rich 72px holding a title, an attachment chip, two lines of preview, and an edit stamp. Four things. Its numbers do not survive being drawn — and the module's real problem is not the row at all: it is that two docs describe how a note is born and they disagree, one of them in its own closing sentence: "Does not require the user to pick anything."

The note row

notes.md §The note row specifies three parts: Title (or first line) with an [attachment chip] opposite it, a two-line preview, and Edited 2d ago. Row height is row-rich (72px).

That is four lines of text. At the token sizes the doc implies — title type-title-3 17/24, preview type-callout 15/20 ×2, stamp type-footnote 13/18 — the text is 82px before any padding. The row has 72px.

Four parts, three lines of spec, one 72px row.

Where a note comes from

Two docs describe how a note is born. 06-flows/capture.md, on what happens when Tier 1 parses a capture as a note: "Note. Created with note.created, attached to today's Day by default." Its closing section is called "What capture does not do" and its first line is: "Does not require the user to pick anything."

05-modules/notes.md, on the Notes mode's +: "The New note action opens the attachment target picker rather than a bare editor, because a note without a parent is not a thing this app has."

Both are true, and they disagree about whether writing a note requires a decision. The app already has a default parent for a note — today's Day — and the Notes mode is the one place that refuses to use it.

The editor

notes.md §Surfaces: "A markdown editor. Title field at top, body below. Autosaves on blur and every 5 seconds while typing (note.edited). No save button."

02-architecture/event-log.md defines note.edited as { note_id, body, title? } — the whole body, not a diff — and contains no coalescing rule. The log is append-only. So the note editor's timer sets the log's write rate, and the log's unit is a whole document.

And the module's one reversal affordance is attached to the attachment: reattaching produces an undo toast, while the body — which saves itself, unattended, 720 times an hour — has no stated way back.

Title, body, autosave line. No save button, no undo.

Reading a note

notes.md §Auto-linking: a Person's name in the body renders as a tappable link only if both hold — the name is Title Case exactly as in the People list, and the Person "has appeared in a prior interaction (task, event, or note) within the last 90 days".

The first condition is about the text. The second is about today's date. So a note is not a stable document: the same bytes render differently in October than they did in September, and the user gets no signal that a link was suppressed. Nothing about the note changed; the calendar moved.

Also in this section, from adjacent paragraphs: the note detail is in "read-only mode" and "tapping opens the editor"; and the Daily Note "appears in three places", two of which ("Recent and Daily scopes") are both inside the Notes mode.
